DOCS / INTRODUCTION

Meet your operating companion.

JARVIS OS is an open-source, local-first desktop AI system. It combines live voice and vision, native computer actions, durable memory, specialist agents, long-running execution, and optional service connectors inside one cinematic command interface.

What it is not

JARVIS is not merely a chat skin, and it is not fully offline unless you choose and configure local model, speech, and voice components. Cloud-backed features send selected requests to their configured providers.

01 / GET STARTED

Quick start

Clone the repository, let the installer validate your host and filter dependencies for your operating system, then launch the application.

TERMINAL
git clone https://github.com/mafk21/OS.git
cd OS
python3 install_jarvis.py --install --launch

On Windows, use py if python3 is unavailable. After installation, the native launchers are:

PlatformLauncher
WindowsStart_JARVIS.bat
macOS./Start_JARVIS.command
Linux./Start_JARVIS.sh

02 / HOST

Requirements

  • Python 3.11 or newerThe installer checks compatibility before changing the environment.
  • A graphical desktop sessionRequired for the full HUD and computer-control features.
  • Microphone and speakersOptional for voice; typed operation remains available.
  • At least one intelligence pathConfigure OpenAI, Gemini, or supported local components.
  • Host permissionsAccessibility, microphone, screen recording, or automation permissions are requested only where the operating system requires them.
Hardware reality

Local models need enough RAM or VRAM for the model you select. Cameras, audio devices, GPU acceleration, desktop APIs, and window managers differ by machine; missing capabilities must produce an explicit limitation rather than a fake success.

03 / ONBOARDING

  2. 2

05 / INTERACTION

Voice, text, and vision

JARVIS supports full-duplex voice, immediate interruption, typed commands, silent HUD workflows, and visual grounding. The system can use the current screen or a requested capture to understand what is actually happening instead of relying only on a description.

Provider behavior

  • OpenAI and Gemini paths provide live voice and multimodal intelligence when configured.
  • Provider failover can preserve continuity when a configured path becomes unavailable.
  • Optional offline STT, LLM, and TTS components can reduce or remove cloud dependence.
  • Visual access is subject to OS screen-recording permissions.

06 / IDENTITY

Guardian and Confidante

Guardian

Commanding, grounded, assertive, protective, and presented through the male humanoid edition.

Confidante

Authentically warm, direct, capable, and presented through the female humanoid edition.

Edition affects presentation, relationship style, visual identity, and voice—not technical capability or authority. JARVIS must never claim consciousness or biological emotion as fact.

07 / CONTINUITY

Memory and learning

The brain preserves continuity without treating every utterance as permanent truth. It can retain approved preferences, commitments, relationships, project context, imported documents, learning progress, and session history in local stores.

Forever timeline

Continuous history across voice, desktop text, and supported channels with epoch compression.

Searchable memory

Retrieval over relevant history rather than dumping all prior context into every request.

Subject learning

Sourced units, quizzes, recorded gaps, mastery tracking, and continuation across sessions.

Owner controls

Privacy toggles, JSON export/import, deletion paths, and learning-category controls.

08 / WORK

Actions and long-running tasks

JARVIS can invoke discoverable tools directly or execute ordered workflows outside the immediate conversation. Long tasks checkpoint before and after each step, expose live progress, preserve outputs, and can consume earlier step results.

No invented completion

Media monitoring waits for the real browser completion event. File monitoring waits for a real file change. Workflows preserve real errors and evidence rather than immediately claiming success.

Crash and side-effect safety

If the application stops during an action, that step becomes uncertain and the workflow enters review. JARVIS does not blindly repeat a possible message, upload, deletion, purchase, or other side effect. The owner chooses whether to retry or mark it complete.

09 / INTERFACE

HUD and background mode

The APEX-based HUD shows the humanoid edition, activity queue, worker agents, logs, system controls, memory and connector panels, media, and live state. Compact background mode keeps voice and work available without occupying the full display. Typed entry and silent workflows remain available when voice is inappropriate.

12 / EXTENSIBILITY

Skills and specialist agents

Skills are reusable playbooks that give an agent structured instructions and boundaries. Included workflows cover research, coding, workspace communication, meetings, file organization, system diagnosis, focus, daily briefing, second-brain work, and topic learning.

Specialist companions can be delegated focused work while the main conversation continues. Worker status and outputs remain visible instead of disappearing behind a generic loading indicator.

13 / PROACTIVE WORK

Automations

Recurring automations and heartbeat-style checks can perform scheduled work. They remain constrained by available tools, permissions, host uptime, and configured providers. A stopped computer cannot observe an event while it is offline, so JARVIS keeps that work pending instead of inventing a result.

14 / REMOTE CONTROL

Remote control

The private LAN dashboard is opt-in. It does not bind a LAN port or request a firewall rule when JARVIS launches. It starts only when the owner explicitly activates Remote Control, creates a pairing key, and shares the generated address on a trusted network.

Network warning

LAN access expands the attack surface. Use trusted networks, protect pairing material, revoke access when finished, and do not expose the dashboard directly to the public internet.

15 / SAFETY

Safety model

  • Confirmation gatesSensitive operations pause for real owner approval.
  • Scoped toolsActions are routed through explicit capabilities rather than unbounded claims.
  • Reversible operationsDestructive changes use safer alternatives when supported.
  • Encrypted vaultCredentials are protected locally; the vault key and runtime secrets are excluded from Git.
  • Tamper-evident auditAction records use a SHA-256 hash chain to reveal modification.
  • Honest failureMissing permissions, dependencies, or host support must be reported, not fabricated.

16 / DATA FLOW

Privacy

On a default local installation, application state is created on your machine. Data leaves only through a feature that inherently uses a remote destination—such as a configured cloud model, web search, connector, upload, webhook, remote channel, or account action.

STAYS LOCAL

HUD, orchestration, SQLite memory, local documents, automations, action history, encrypted credential vault, local models, and local speech components.

LEAVES WHEN ENABLED

Cloud-model prompts, provider-required context, messages, uploads, search queries, connector operations, and telemetry a third-party dependency may independently collect.

For the authoritative disclosure and zero-cloud checklist, read PRIVACY.md ↗.

17 / LOCAL STATE

Storage and publication hygiene

Runtime databases, API keys, OAuth tokens, vault keys, browser sessions, memories, routines, recordings, screenshots, imported knowledge, generated files, and caches are excluded from source control. Repository tests guard against tracked runtime identities, private storage paths, and high-confidence credentials.

If a real secret is ever committed, deleting it later is not enough: revoke it immediately and purge it from Git history.

18 / SUPPORT

Troubleshooting

The HUD does not launch

Run python3 install_jarvis.py --check. Confirm Python support, required packages, a graphical session, and the prebuilt HUD. Review the terminal output for the real missing dependency.

Voice input or output is missing

Confirm microphone permission, selected devices, audio backend availability, provider credentials, and that silent mode is not active. On Linux, check PipeWire/PulseAudio tools.

Screen or desktop control does not work

Grant Accessibility and Screen Recording permissions on macOS. On Linux, behavior depends on X11/Wayland and the desktop environment. On Windows, elevated actions may require approval.

A cloud connector fails

Reconnect the provider, confirm token scope and expiry, review rate limits, and verify the provider has not changed its API or web interface.

A long task stopped after restart

Inspect its state. If a step is marked uncertain, decide whether retrying is safe or mark it complete based on external evidence.

20 / BOUNDARIES

Known boundaries

  • JARVIS is powerful software, not a guarantee that every third-party site, API, peripheral, or desktop environment will remain compatible.
  • Local AI quality and speed depend on model choice and hardware.
  • Cloud providers and connectors operate under their own privacy policies, prices, limits, and availability.
  • Computer-control actions can affect real files and accounts; review sensitive operations.
  • The assistant is not conscious and must not represent simulated relationship behavior as biological emotion.
  • Remote access should not be directly exposed to the public internet.
